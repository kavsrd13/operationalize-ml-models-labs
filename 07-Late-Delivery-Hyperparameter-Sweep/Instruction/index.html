Exercise 07: Tune late-delivery classification

Goal

Tune logistic regression on pre-April training and April–May validation data. Keep June–August test labels out of selection.

Fork and clone the public repository

Install Python 3.10 or 3.11, Git, Azure CLI, and a notebook editor. The public course repository can be inspected or cloned without a GitHub login:

git clone https://github.com/kavsrd13/operationalize-ml-models-labs.git
Set-Location .\operationalize-ml-models-labs

To save your exercise work in your own GitHub account, sign in at GitHub, open the course repository, select Fork, and then select Create fork. Clone your fork instead of the upstream repository:

git clone https://github.com/YOUR-GITHUB-USERNAME/operationalize-ml-models-labs.git
Set-Location .\operationalize-ml-models-labs
git remote add upstream https://github.com/kavsrd13/operationalize-ml-models-labs.git
git remote -v

No gh auth login command is needed for cloning. GitHub sign-in is required only to create the fork or push changes to it.

Create or reuse Azure resources for this lab

Set your own subscription, resource group, workspace, and region. The commands create the group and workspace if needed, install the shared Olist asset, and create one scale-to-zero training cluster named course-cpu. Reuse the same names in later labs. Check regional quota for Standard_E4ds_v4.

$SUB = 'YOUR_SUBSCRIPTION_ID'
$RG = 'rg-course-ml'
$WS = 'mlw-course-ml'
$LOCATION = 'eastus'
az login
az account set --subscription $SUB
az extension add --name ml --yes
az group create -n $RG -l $LOCATION
az ml workspace show -n $WS -g $RG --subscription $SUB 2>$null | Out-Null
if ($LASTEXITCODE -ne 0) {
  az ml workspace create -n $WS -g $RG -l $LOCATION --subscription $SUB
}
python .\00-Shared-Setup-and-Data\scripts\bootstrap.py `
  --subscription $SUB --resource-group $RG --workspace $WS --create-cluster
az ml compute show -n course-cpu -g $RG -w $WS --query name -o tsv
az ml data show -n olist-ecommerce-raw -v 1 -g $RG -w $WS --query name -o tsv

Code files

The actual code for this exercise is here:

  • Azure ML late delivery sweep.ipynb

  • src/sweep_train.py

Run commands from the repository root. Olist's source ZIP is stored once in datasets/olist and extracted by setup.

Steps

  1. Confirm the setup above created course-cpu. Open ../Azure ML late delivery sweep.ipynb with the Olist kernel.
  2. In notebook step 1 leave REGISTER_RESOURCES and SUBMIT_SWEEP at False. Run preparation and inspect the generated train/validation MLTable and Parquet files.
  3. Set REGISTER_RESOURCES = True and rerun the registration cell. Verify olist-late-sweep-train:1, olist-late-sweep-validation:1, and olist-sweep-env:2 in the shared workspace.
  4. Read ../jobs/sweep-smoke.yml, ../jobs/sweep.yml, and the trial script. The smoke job uses fixed values; the full sweep has at most eight trials, one concurrent trial, and a 300-minute limit.
  5. From the collection root, run the smoke job and wait for Completed:
   $SMOKE_JOB = az ml job create -f .\07-Late-Delivery-Hyperparameter-Sweep\jobs\sweep-smoke.yml `
     -g $RG -w $WS --query name -o tsv
   az ml job show -n $SMOKE_JOB -g $RG -w $WS --query status -o tsv

Repeat the status command until it says Completed. Streaming is optional; some Azure CLI versions report Incorrect padding after a successful job.

  1. Set SUBMIT_SWEEP = True in notebook step 1 and run the sweep submission cell once. The job name is saved in ignored .sweep-run-id.json to avoid duplicate submissions. Alternatively submit ../jobs/sweep.yml with az ml job create -f using the same group and workspace.
  2. In Studio inspect average precision and late-class precision/recall for every trial. Record the selected settings and explain why validation results are not a final future-period test.
  3. Reset the notebook submission flags to False after the run.
